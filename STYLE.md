# STYLE.md — Правила и соглашения API библиотеки

Этот документ описывает ключевые правила проектирования, бизнес-логику и стилистические соглашения для REST API библиотеки.

## 1. Именование и формат данных
*   **URL (пути)**: Используется `kebab-case` (слова через дефис). Ресурсы именуются во множественном числе. Пример: `/books`, `/readers`, `/loans`.
*   **Тело запроса и ответа (JSON)**: Используется `snake_case` (слова через нижнее подчеркивание). Пример: `book_id`, `due_date`, `available_copies`.
*   **Версионирование**: Все эндпоинты располагаются под префиксом `/v1/`, который задается в базовом URL (`servers`).

## 2. Соглашения по HTTP-методам
*   `GET` — только для чтения данных (идемпотентный).
*   `POST` — для создания ресурсов или выполнения действий (например, возврат книги).
*   `PUT` — для полной замены существующего ресурса.
*   `PATCH` — для частичного обновления ресурса.
*   `DELETE` — для удаления ресурса.
*   **Коды ответов**: `201 Created` при создании, `204 No Content` при удалении, `200 OK` при успешном чтении/обновлении. Ошибки возвращают соответствующие `4xx` (например, `400`, `401`, `403`, `404`, `409`, `422`) или `5xx`.

## 3. Бизнес-правила выдачи книг (Loans)
*   **Проверка доступности**: Выдача книги возможна только при условии `available_copies > 0`.
*   **Лимит на читателя**: Один читатель может иметь не более 5 активных выдач одновременно (где `returned_at == null`).
*   **Срок возврата**: Поле `due_date` при создании новой выдачи должно быть строго позже текущей даты.
*   **Возврат книги**: Реализуется через `POST /loans/{id}/return`, а не через удаление (`DELETE`). Повторный возврат должен быть идемпотентным.
*   **Вычисляемые поля**: Поле `available_copies` вычисляется сервером на основе `total_copies` и активных выдач. Клиент не передает это поле в запросах.

## 4. Фильтрация и пагинация
*   Все коллекции (`/books`, `/readers`, `/loans`) поддерживают пагинацию через query-параметры `page` и `per_page`.
*   Коллекции поддерживают сортировку через параметр `sort` (префикс `-` означает сортировку по убыванию).
*   Специфичные фильтры: `/loans?status=overdue` возвращает только просроченные выдачи (где `due_date < now` и `returned_at == null`).

## 5. Идемпотентность и защита от дублей
*   Запросы `POST /loans` обязаны содержать заголовок `Idempotency-Key`.
*   Ключ хранится на сервере 24 часа. При повторной отправке с тем же ключом и тем же телом возвращается полный replay исходного ответа.
*   При повторной отправке ключа с другим телом возвращается ошибка `409 IDEMPOTENCY_MISMATCH`.

## 6. Правила удаления (Delete)
*   Запрещено удалять книгу (`DELETE /books/{id}`) или читателя (`DELETE /readers/{id}`), если у них есть активные выдачи.
*   При попытке такого удаления возвращается ошибка `409 BUSINESS_RULE_VIOLATION`.

## 7. Единый формат ошибок
Все ошибки возвращаются в едином формате `Error`:
*   `status_code` (integer) — HTTP-код.
*   `code` (string) — машинночитаемый код из фиксированного `enum` (`INVALID_REQUEST`, `NOT_FOUND`, `VALIDATION_ERROR`, `CONFLICT`, `BUSINESS_RULE_VIOLATION`, `IDEMPOTENCY_MISMATCH`, `FORBIDDEN`, `UNAUTHORIZED`).
*   `message` (string) — человекочитаемое описание.

## 8. Временные метки
*   Все временные метки (например, `loaned_at`, `due_date`, `registered_at`) передаются в формате UNIX timestamp (целое число секунд с 1970 года).
*   Серверные метки времени (`registered_at`, `loaned_at`) доступны только для чтения (`readOnly: true`).
